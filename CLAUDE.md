# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Portfolio is a native Jellyfin client for Apple platforms, built in SwiftUI. tvOS ships first; iOS, visionOS and macOS follow and share code through `PortfolioKit`. Playback uses AetherEngine for the best video quality, including Dolby Vision Profile 7 FEL. Broad Jellyfin plugin support and ecosystem tools like Seerr are goals.

Code conventions are in @style.md.

## Commands

Everything needs Xcode 27. There's no linter. Set the destination first:

```bash
DEST='platform=tvOS Simulator,name=Apple TV 4K (4th generation)'
```

```bash
# App unit tests, as CI runs them
xcodebuild test -workspace Portfolio.xcworkspace -scheme PortfolioTV -destination "$DEST" \
  -only-testing:PortfolioTVTests -parallel-testing-enabled NO -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO

# App UI tests. These must be signed: without signing the app can't write to the Keychain,
# so the sample sign-in silently stays on onboarding and the tests fail there.
xcodebuild test -workspace Portfolio.xcworkspace -scheme PortfolioTV -destination "$DEST" \
  -only-testing:PortfolioTVUITests -parallel-testing-enabled NO -skipPackagePluginValidation

# One UI test
xcodebuild test -workspace Portfolio.xcworkspace -scheme PortfolioTV -destination "$DEST" -parallel-testing-enabled NO \
  -skipPackagePluginValidation -only-testing:PortfolioTVUITests/AppNavigationUITests/testTheSidebarOpensOnTheCurrentSection

# Package tests (run from PortfolioKit/)
xcodebuild test -scheme PortfolioKit-Package -destination "$DEST" -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO

# One package test (Swift Testing needs the parentheses)
xcodebuild test -scheme PortfolioKit-Package -destination "$DEST" -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO \
  '-only-testing:PortfolioSharedUITests/RootViewModelTests/showsTheRightViewForEachSessionState(_:_:)'

# Release build for a real Apple TV. Release for the simulator doesn't link (#27).
xcodebuild build -workspace Portfolio.xcworkspace -scheme PortfolioTV -configuration Release \
  -destination generic/platform=tvOS -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO

# Confirm the shared UI still builds for other platforms (run from PortfolioKit/; also visionOS)
xcodebuild build -scheme PortfolioSharedUI -destination generic/platform=iOS -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO
```

CI builds the app and runs the app unit tests and package tests on every PR. UI tests aren't in CI yet (#26), so run them locally when changing anything on screen. `-test-iterations` must be at least 2. SourceKit's "No such module" errors are noise; trust `xcodebuild`.

A simulator build with `CODE_SIGNING_ALLOWED=NO` and a signed UI test run share DerivedData, and the UI tests can end up launching the unsigned app, which the simulator refuses ("Security policy issue", or a launch `RequestDenied`). Run `xcodebuild build-for-testing` without that flag to sign it again.

Xcode and command-line builds of the workspace share one DerivedData folder, so building from the command line while the owner builds in Xcode can leave either compiling against the other's stale modules. Command-line builds alongside Xcode should pass their own `-derivedDataPath`, with `-clonedSourcePackagesDirPath` pointing at the shared folder's `SourcePackages` to reuse the packages.

Interrupting a build (killing `xcodebuild`, or a "build database is locked" failure from two builds at once) can leave later builds reporting success without relinking the app, so the simulator runs old code. Check `PortfolioTV.app/PortfolioTV.debug.dylib`'s timestamp in this project's DerivedData folder (there can be more than one), and if it's stale, delete `Build/Intermediates.noindex/PortfolioTV.build/Debug-appletvsimulator` and the built `.app` there. A clean build of everything takes about a minute, so a build running far longer is stuck rather than slow: delete that DerivedData folder's `Build` (keeping `SourcePackages`) and build again.

## Architecture

`Portfolio.xcworkspace` combines `PortfolioTV/PortfolioTV.xcodeproj` (Xcode 27's `project.xcproj` format) and the local package `PortfolioKit/`. The project uses folder references, so new files under `PortfolioTV/` join their target automatically.

**Modules**
- `PortfolioShared`: models any media server could produce, plus the saved servers, sessions and Keychain persistence. No Jellyfin types.
- `PortfolioSharedJellyfinClient`: wraps jellyfin-sdk-swift and owns everything Jellyfin-specific, such as `ServerVersion` and the SDK mapping.
- `PortfolioSharedPlaybackEngine`: the engine-neutral playback layer and `PlaybackEngine` protocol.
- `PortfolioSharedAetherPlaybackEngine`: the only module that imports AetherEngine.
- `PortfolioSharedUI`: views every platform can use, and the view models of screens each platform draws its own way (profiles and onboarding), so another platform only adds views.
- `PortfolioTV` (app target): tvOS-only views, and the composition root. `PortfolioTVApp` makes the one `JellyfinServerClient` and the `SessionManager` (Keychain storage, with the client as its authority), and passes both to the shared `RootView` along with how to make its `ProfilesView` and `MainNavigationView`. `RootViewModel` hands the services to the view models it makes: a fresh `ProfilesViewModel` each time no profile is open, and a `CurrentProfileViewModel` for each fresh main UI, so every profile opens on Home.

The app target defaults to `MainActor` isolation and the package doesn't, so test suites for app code need `@MainActor`. Tests for app code go in `PortfolioTVTests`. Unit tests talk to `MockJellyfinServer`, an in-process fake built on `URLProtocol` that listens on a given scheme, host and port. It and `JellyfinServerClient.mocked`, which sends requests to it, are in `PortfolioSharedTestSupport`.

`PortfolioTV/Info.plist` sits outside the app's folder and holds only what build settings can't express: App Transport Security allows plain HTTP, because most Jellyfin servers on a home network are `http://…:8096`. Xcode merges it with the Info.plist it generates.

**Profiles and onboarding** (`PortfolioTV/Profiles/`, `PortfolioTV/Onboarding/`, view models in `PortfolioSharedUI`).
- Every launch opens on the profile picker ("Who's watching?"): everyone on every server added to this device, signed in or not, plus "Someone Else". A fresh install opens on the welcome screen instead. No profile is open until one is picked (`SessionState.choosingProfile`). The picker starts with focus on the profile opened last (`SessionManager.lastOpenedProfile`, saved by `MediaServerStore` under its own key), without opening it.
- The open profile sits at the top of the sidebar (`CurrentProfileView`), its server's name reading "Switch Profile" while focused. Selecting it closes the profile without signing it out (`SessionManager.closeProfile()`), back to the profile picker.
- "Someone Else" on the profile picker leads to a server picker (`ServerPickerViewModel`): the servers added to this device, with their icons, where someone types their username (anyone the server lists is on the profile picker already), and "Add Server", which starts at the welcome screen.
- `SessionManager` holds the saved servers (`MediaServer`: the server, the users this device knows, and the access token of each signed-in user), stored in the Keychain by `MediaServerStore`. Opening a profile checks its token with the server first; offline still opens, and a revoked token asks for the password. Signing out keeps the profile on the picker. Settings' "Remove All Servers (Debug)" (`SessionManager.removeAllServers()`) starts over as if freshly installed; deleting the app doesn't, because the Keychain outlives it.
- Adding a server goes welcome → address and port (without a scheme, HTTPS first, then HTTP on 8096; see `ServerAddress`) → the users the server lists (`/Users/Public`), or straight to signing in with a username when it lists nobody → their password, beside the server's branding (its icon, and its splash image and login message, if set). "Someone Else" covers users the server hides.
- `ProfilesViewModel.path` holds the pushed steps (`ProfilesViewModel.Step`) with their view models. Navigation values must be `Hashable`, so `Step` compares by view model identity: each step is equal only to itself.
- User pictures and the splash come through `JellyfinServerClient.imageURL`, as PNG at full size: those endpoints have no size or quality options, and PNG keeps the server from compressing them again. The splash fills the sign-in screen's right half without stretching (`scaledToFill`), blurred and dimmed under the server's icon and name: filling a nearly square half crops and enlarges a 16:9 image.
- The server's icon is the largest one its web client lists in `/web/manifest.json` (the file names carry a content hash in some versions, so they aren't guessed). A server without its web client gets a stand-in.
- "Use Your Phone" is a disabled stand-in for Quick Connect (#8).

**Browsing and card transitions** (`PortfolioTV/MediaBrowsing/`). The motion copies the Apple TV app and is plain SwiftUI state animation, with no UIKit or `matchedGeometryEffect`.
- `ViewState` (`.root`, `.preview`) is inherited through the environment. A browsing view at `.root` shows posters. Entering `.preview` turns the open row's cards into platters. Setting the previewed card's own `viewState` to `.root` expands it to full screen.
- A card can also go **straight from poster to full screen**, skipping the platter, with nothing else moving: its parent sets the card's own `viewState` to `.root` while it's still a poster (no change at `.root`), then enters `.preview`. Back reverses it. `MediaCardExpansionViewModel` and `MediaCardExpansionView` do this for one card, which is how the library grid opens an item. A parent view model always drives the card's states: `MediaBrowsingViewModel` for rows, `MediaCardExpansionViewModel` for a single card. The card never animates itself.
- A `RelatedMediaGroup` is drawn by `RelatedMediaGroupPosterView` at rest and by `RelatedMediaGroupCarouselView` once open. Both watch one `RelatedMediaGroupViewModel`, which holds the highlighted item, focus state, cards and where each poster is. There are two views because the open cards sit above the whole browsing view, and SwiftUI can't move a view between parents mid-animation.
- There's one `MediaCardViewModel` per item, shared by a poster and the card that grows out of it. `MediaItemLayout` is pure geometry giving each card and its artwork a frame for any point of a motion.
- `MediaBrowsingViewModel` owns the order of events. Opening places the cards exactly on their posters (which hide underneath), then enters `.preview`. Closing does the reverse.
- **Artwork:** every card draws its poster with its landscape art (the backdrop, which has no title on it, else the thumbnail) on top. The landscape art's opacity follows the card's form (`showsLandscapeArtwork(in:)`): 0 on a poster, 1 once a poster widens and on platters and full screen. That changes inside the animation that moves the card, so the picture cross-fades as the card widens, grows or shrinks. The fade has its own timing, for opacity alone: a poster filling a card that's getting wider zooms in, so the landscape art covers it quickly, early on. As a card narrows or shrinks back to a poster, it uncovers it just as quickly, early, so the poster shrinks with the card. The landscape art is only drawn while it shows, or while the card is warm (the highlighted card and `neighborsDrawn` each side), which loads it ahead of time so it's ready to fade into, and keeps only a few screen-sized images in memory.
- A card's poster always fills the card, so it grows and shrinks with it. A platter's landscape art is as big as the screen (`MediaItemLayout.artworkFrame`), and the card clips it. The open card's poster's art fills it; a neighbor's, unseen on a poster, also reaches the screen's edge on the side it moves to, since its platter's art reaches only a little past that edge while the card reaches far beyond. Cards further from the open one than `neighborsDrawn` stay posters (`waitsOffScreen`) and wait off screen, pushed as far as the furthest platter's outer edge moves, so the rest of the row slides away together, spaced as it was. Midway, the art also grows if it must to cover the part of its card on screen (`MediaItemLayout.covering`). In a row of wide cards, whose posters already show their art, opening moves the art from filling its card to where a platter's sits all the way, growing with the card; closing fits it back to its card early (by `artworkSettling`, half open) and shrinks it with the card (`MediaItemLayout.isClosing`). A neighbor's platter art is centered near the screen's middle while its card is mostly off it: closing all the way, the picture slid one way under its card while the card went the other, so the cards seemed to bounce; opening the other way, the pictures held still in their cards and then swung into place. Far cards that all waited at one spot passed over each other on the way back.
- **The carousel animates three numbers, not frames** (`RelatedMediaGroupCarouselCardsView`, an `Animatable` view): how far the row has opened (`progress`), how far the open card has expanded (`expansion`), and where the open card is while the row slides (`openPosition`). On every frame `MediaItemLayout` places every card and its artwork from that one point of the motion. Letting SwiftUI animate each card's `.position` and `.frame` and its artwork's frame on their own, on an Apple TV the open (focused) card started a few frames after its neighbors and on another curve, and the art fell out of step with its card, showing the poster around it or a second copy of the art; the simulator showed none of it. `MediaItemLayoutTests` checks that no two cards overlap and the art covers each card on screen at every step of opening, closing, expanding and sliding. The open card's artwork is centered, and each neighbor's sits `artworkParallax` toward its side, so sliding along the row moves the artwork far less than the cards. Each platter uncovers its artwork as it slides in, a parallax. Expanding uncovers the rest of the open card's artwork without moving it.
- Posters are fetched at the size they rest at and landscape art at the screen's (`MediaBrowsingView` measures the screen), so a wide poster, its platter and full screen show the very same image, which grows with the card.
- **Posters have no titles**, as in the Apple TV app. Each is drawn in its own shape (`posterAspectRatio`, from the server's `PrimaryImageAspectRatio`, so the row lays out before images load): a movie poster is 2:3, an episode's still 16:9. A wide poster shows the item's logo, small, at its bottom-leading corner, or its title if it has none, and a platter's and full screen's details show the logo in place of the title too. Logos are fetched once, at the details' size (`detailsLogoSize`).
- **Home** (`HomeViewModel`, `PortfolioTV/Home/`): a banner filling the screen that goes through the 8 newest items (`HomeBannerView`, driven by `HomeBannerViewModel`), then Continue Watching overlapping the banner's bottom, then a Latest row per library in the user's order, leaving out the libraries in their `LatestItemsExcludes` and collections, playlists and Live TV. Continue Watching is what they're partway through, then the next episode of each show they're watching that isn't already there; it's a `RelatedMediaGroup` of style `.inProgress`, whose cards are wide (480 by 270) from the start, never widen further, and show their progress, episode ("S1E5") and time left. They fetch landscape art at their own size until they're warm (`restingLandscapeArtworkSize`), so a row of them doesn't hold a screen-sized image per card.
- The banner is the browsing view's header, reaching past its safe area with negative padding (`MediaBrowsingView`'s `topPadding: 0`, and its scroll view doesn't clip). Left and Right (and ›) move between its items; Right and › go round from the last to the first, and Left from the first brings in the sidebar. Focus stays on the button it's on through a move, and coming up from the rows lands on the button it was on last (`HomeBannerViewModel.lastButton`). Moving on, its text and buttons fade out, then the next banner's edge sweeps in from the right (the previous one's from the left) over the one showing, uncovering its artwork in place (a mask), and the text fades back in. Its text fades out over 0.25 s and back in over 0.3 s, each logo its own view so the last one doesn't cross-fade into the next. It moves on by itself every 8 s while Home shows, stopping at the last, counting again as each banner settles; the system page indicator (`UIPageControl` with a `UIPageControlTimerProgress`, which only shows it) draws the current page as a dash filling over that time. Its details are the very block a full-screen card shows (`MediaDetailInfoView`, with the metadata line), its buttons sitting `actionsReservedHeight` below them as a card's actions do. Info makes the banner itself the item's full-screen detail view (`HomeBannerViewModel.showsDetails`, in card motion's curve): the details move to where a full-screen card has them, the banner's buttons cross-fade into the card's actions (`MediaDetailActionsView`), its scrim into a card's (`MediaCardView.detailsScrim`), and the rows fade out. Focus stays on Info through the move, faded to 2%, and moves to Go deeper once it's over; Back reverses it, focus staying on Go deeper and moving to Info at the end (`detailsAreMoving`, then `settled()`). Laying a full-screen card over the banner to take over instead, its actions went a frame before it did, and the buttons blinked out. While the details are away (`detailsAreAway`) the page doesn't scroll, since tvOS scrolled it to show a low button getting focus, and the edge catchers are off; only then can the actions take focus, since hidden they still drew Left and Right. The details' logo loads at `.high` priority: queued behind every poster, the banner showed none for seconds. The Play buttons wait for #15.
- An episode borrows its show's thumbnail, backdrops and logo when it lacks its own: `EpisodeInfo.seriesImages` holds the show's tags, and `MediaItem.image(_:)` gives the item's own image or else its show's, with the item it belongs to, for the resolver's URL. Jellyfin can point an episode at its season's art instead; that's left out. So its card shows the show's art and logo, and its details read "S1E5 · The Bridge · 2022 · 52m" under the show's title.
- Sections stay alive while another shows, so a section that loads from the server loads again each time it's shown (`HomeView`'s `task(id: isShowing)`), keeping its rows up until new ones arrive and leaving them untouched if nothing changed. The debug sample session's server doesn't exist, so Home says it can't reach it (which UI tests wait on to know Home is showing), it has no libraries, and UI tests use Search's sample row for posters. The library views are covered by unit tests and checked by hand against a stand-in server.
- **A load a view starts from `task` belongs to its view model, not to the task.** SwiftUI cancels and restarts Home's `task` moments after the main UI opens. A load running in that task was cancelled while a real server was still answering, and Home stayed empty. Fast mock servers answer in time, so only a slow server (a delayed stand-in will do) shows it.

Things that break easily here:
- **Card motion is a curve that stops at its end** (`layerChange`: a timing curve shaped like `.smooth(duration: 0.44)`), and **what swaps views when a motion ends waits for `.removed`**. A spring is logically complete at its nominal duration while it's still a few percent short: closing a row removed the cards there, and they jumped onto their posters, 50 points or more for a far card, worse on an Apple TV, which also stalls for a frame or two as focus moves and the carousel goes. Waiting for a spring to be removed instead left the screen still for a third of a second while it crept the last pixel. Track an edge frame by frame through a motion's last frames to see either; tiles don't show them.
- **Back while a row is still opening is held until its cards have grown** (`MediaBrowsingViewModel.closesOnceGrown`), then they close straight back onto the poster, which kept focus and so is still lifted. Opening and closing move a row of wide cards' pictures along different paths, so turning round partway made them jump.
- **The carousel places its cards from the layout on every frame,** so anything the layout reads changes the motion's endpoints at once: `startsLifted` turns off only once the cards have grown, or they'd start from the smaller, resting poster.
- **Each section's page is a `compositingGroup()`** (`MainNavigationView`). A view pushed over it fades it layer by layer otherwise, and what's covered shows through: a full-screen card's poster under its backdrop, and the rows behind the card. It costs nothing at rest, only while an ancestor fades it.
- **Focus never moves while cards animate.** A tvOS focus update at the start of an animation stalls its first frames, so sequence with `withAnimation(_:completionCriteria:_:completion:)`.
- **Closing gives the poster focus just before removing the cards**, or tvOS picks a poster itself and the row's first one flashes. Focus passes through `nil` during this, and that gap mustn't count as focus leaving the row.
- `@FocusState` can only live in a view. View models take the binding as a parameter. Don't mirror focus into a view model property: the extra update breaks the close hand-off.
- **Every platter shows its actions** (Play, Go deeper) under its details, as a full-screen card does, drawn above it by `RelatedMediaGroupCarouselCardsView` since a card is a button and can't hold others. They move with the card, so growing to full screen and back fades nothing; they take focus only on the open card at full screen (`MediaDetailActionsView`'s `isActive`). Inactive, they're one hidden accessibility element, but XCUITest on tvOS still lists their buttons, so UI tests find Go deeper inside `detail.fullScreen`.
- **Labels stay out of the motion:** the ones showing fade out as cards start moving (in their own quick animation), and the next ones fade in only once cards have stopped.
- A focused poster's card starts at the size tvOS lifts it to (`liftScale(forWidth:)`: 10.8% of its width, but no more than 40 points, which fits 4K frames of a poster, a Continue Watching card and a wide poster), so the hand-off is invisible.
- Focus staying on a poster for 5 seconds widens it in the row to at least 16:9, never narrowing one that's wider, and turns it to its landscape art; this deliberately differs from the Apple TV app, and trailers will start there. **The poster row must not be a `LazyHStack`:** it re-estimates off-screen positions from a measured wide poster and the row jumps. A scroll view also can't scroll into width that's still animating in, so the row adds trailing room just before a poster widens. Don't keep that room permanently, or tvOS rests the last poster far from the edge.

**Libraries** (`PortfolioTV/Libraries/`, view models in `PortfolioSharedUI/Libraries/`).
- The profile's libraries load when the main UI opens (`LibrariesViewModel`) and join the sidebar: one entry per standard kind (Movies, TV Shows, Collections, Playlists, Music Videos), combining every library of that kind (`LibraryScope.kind`), then a separator, then libraries on their own (`LibraryScope.library`): every library of another kind, and each library of a standard kind that has several, such as "4K Movies". Settings comes last.
- A library view (`LibraryViewModel`) has its own sidebar (`LibrarySidebarView`), whose items (`LibrarySidebarItem`) are Recently Added, All Movies or the like, and under "Genres", the genres from Jellyfin. Beside it is a grid of the chosen sidebar item's posters, which keep their size and don't widen: 2:3 posters, 16:9 stills for videos, squares for albums. Selecting a poster grows its card straight to full screen, cross-fading into its backdrop, and Back shrinks it back onto the poster (`MediaCardExpansionViewModel`).
- The grid follows focus on the sidebar items once focus has rested on one for `settleDelay` (0.1 s), so passing over them doesn't swap the grid. To make switching quick, every sidebar item's first page (a small one, 24) loads as soon as the library shows and its genres are known, and the first 16 posters of the focused sidebar item and the ones beside it load as soon as focus reaches it. Each sidebar item's items are kept: going back to one shows it at once, and loads its first page again if it's older than `refreshAfter` (10 s). The grid showing stays until the next has loaded.
- The grid is a `LazyVGrid` (its cells don't change size, unlike a row's posters), loading the next 60 items once an item within 20 of the end comes on screen. It loads again each time the library is shown, like Home. A grid poster getting focus warms its card (`isWarm`), which draws its landscape art unseen under the poster, so it's there to cross-fade into as the card grows; only the focused one's is kept.
- Only the sidebar item showing has a platter (white at 10% opacity, the system's resting gray), with no checkmark; the focused one brightens and grows a little. It's also marked with the `isSelected` trait, not a changed label: a label that changes when focus rests on it loses XCUITest's (and VoiceOver's) hold on it. Coming into the sidebar lands on the item showing (`defaultFocus`), and Back from a poster goes there too: one `LibraryFocus` spans the sidebar, the grid and an expanded card's actions. A new sidebar item's grid cross-fades over the old one.
- **A lazy grid drops rows that leave its frame**, even ones still showing past it with `scrollClipDisabled`, so the grid runs to the top and bottom of the screen (`ignoresSafeArea`), with content margins keeping its first row where the sidebar starts.
- **Artwork for the whole screen is fetched at `GeometryProxy.screenSize`**, a view's size with its safe area added back. Measured inside the safe area, even through `ignoresSafeArea`, the screen came up short and backdrops were scaled up.

**Images** (`PortfolioSharedUI/Images/`).
- Item images come from a `MediaImageResolver`; `JellyfinImageResolver` builds Jellyfin's URLs. Each asks for a pixel size (rounded up to 100 px steps), at quality 100, naming no format, so the server sends JPEG, or PNG for transparent images such as logos. Jellyfin's image endpoints need no sign-in. User pictures, the splash and server icons have no size options and come at full size.
- `ImagePipeline.shared` downloads and decodes off the main thread, keeping decoded images in memory and data on disk (`URLCache`). It runs 8 downloads at once (`DownloadScheduler`), starting the most wanted waiting one first: a card's landscape art and the banner's backdrops are `.high`, posters `.normal`, and what's loaded ahead `.low`. Home asks for every poster of every row at once, and without priorities the art a card grows into waited behind them. Images a view shows stay in memory however full the cache gets (`ImagePipeline.lease`, held by `RemoteImageViewModel`'s layers), so a card growing out of a poster draws the poster's image from its first frame: a screen-sized backdrop is about 33 MB at 4K, a few pushed the posters out of the cache, and cards opened on blank placeholders. Like `URLSession.shared` behind `AsyncImage`, it's shared rather than passed down.
- `RemoteImageView` draws an image already in memory at once, from the first frame, and fades in one that arrives later.
- Cards wait for their artwork on `ImagePlaceholderView`: a translucent gray (the system's resting platter), with a shimmer sweeping over it while the image loads (`isLoadingImage`, set by `RemoteImageView`). The shimmer is drawn from a `TimelineView`, not animated, so it never joins a card's motion.

Things that break easily with images:
- **A cross-fade during a motion is the opacity of an image that's already there, changed inside the motion's animation.** Adding an image view, or changing the image one shows, while a card moves drew blank frames under tvOS's focus highlight, left the new image at a stale size, and blended the old image at its old size. `.animation(_:value:)` around a new image animated its size on the fade's curve, out of step with the card.
- **Anything that shows a card's landscape art changes inside the motion's animation, or after it.** Opening a row widens the poster under the open card only once the cards have grown; widening it first switched the card to landscape art at once, with no fade.
- **Handling a move command doesn't stop tvOS moving focus,** into the sidebar for one. The banner catches Left and Right with a focusable view each side of its buttons, focusable while there's a banner that way (`HomeFocus.bannerLeftEdge`, `.bannerRightEdge`). tvOS chose the sidebar over a thin target far from Info, so the left one fills the disabled Play button's frame, right beside Info (it moves left of Play once Play works, #15).
- **Focus can't move to, or stay on, a view faded out entirely, or a clear one:** the catchers are black at 2% opacity, and the banner's buttons fade only to 2% while banners move, too faint to see, so focus stays on a button, or waits on a catcher, through the move. Faded out entirely, a button lost focus to nowhere as the banner moved on by itself. A catcher stays focusable while it holds focus even once there's nowhere left to go that way. Asked to move off a catcher after a move, focus didn't, so the catcher stops being focusable first (`releaseEdges`), then focus is set a beat later, once the buttons are back.
- **Don't keep a scroll position for the browsing view** (`scrollPosition(_:)`): it puts the scroll view back whenever the view updates, such as while a row opens or closes. Home scrolls to its top with a one-off request instead (`MediaBrowsingView`'s `scrollToTopRequests`), when focus comes up into the banner.
- Every row is a `focusSection()`, so Up and Down always reach the next row, landing on its nearest poster, even where none is directly above or below. Going back to the row focus just came from lands on the poster it left there instead (`MediaBrowsingViewModel.posterLeftBehind`, a `.defaultFocus` with `.userInitiated` priority on each row); moving on from the next row forgets it.
- **A focus section only guides moves from outside its frame.** Continue Watching overlaps the banner's bottom, so a section around the whole banner wasn't "above" its cards, and Up from any card not under a button went nowhere. The section is a strip as wide as the screen around the banner's buttons, entirely above that row.
- **What's drawn inside a poster stays out of accessibility.** The poster button carries the item's name as its label. A wide poster's title appearing and fading inside it made XCUITest (and so VoiceOver) report nothing focused afterwards.
- **Cards' buttons draw their label as it is** (`MediaCardButtonStyle`), never `.borderless`: tvOS lifts each image in a `.borderless` button's label on its own, with its own corners and shadow. On an Apple TV a backdrop drew its own corners inside its moving card, and a poster's corners grew the moment focus came back to it as its card closed. Posters lift with `.hoverEffect(.highlight)` on the whole card; platters show focus by the others' darkening. Check motion on an Apple TV as well as the simulator.
- **Never fade an image out.** A view fading out keeps its last layout, so inside a moving frame it shows beside the new one. Images that go, go at once, once they're covered.

**tvOS behavior that shaped the design**
- The sidebar is a `NavigationSplitView` starting at `.detailOnly`. Search is its first section, as in the Apple TV app, but the app opens on Home. Its sections are `MainSection`s, built from the profile's libraries (`MainNavigationViewModel.mainSections` and `otherSections`), in two list sections; the second's header draws the separator. Its rows are spaced apart with `listRowSpacing`, which tvOS only has from 27. A `.sidebarAdaptable` `TabView` always opens with focus on its sidebar, and nothing moves it out (`@FocusState`, default focus, placement APIs and UIKit focus requests were all tried).
- Sidebar rows must be `NavigationLink(value:)`: `.tag`ged labels get no focus highlight, and buttons don't change the selection. These rows bring the collapsed "‹ Home" pill. It can't be hidden: removing `.sidebarToggle`, hiding the navigation bar of the sidebar or of a section, hiding the tab bar (`.toolbar(.hidden, for: .tabBar)`) on a section or the split view, and fading the sidebar's contents all left it there.
- A button as a row of its own in that sidebar doesn't take focus at all, so the open profile is a button in the section's header. Header content sits closer to the edges than rows, so `CurrentProfileView`'s insets are measured to give its focus highlight the rows' exact edges.
- Sections stay alive in a `ZStack`, so a hidden one must stay disabled or it can take focus.
- `navigationTransition(.zoom)` renders as a cross-fade on tvOS.

**Checking motion.** Tests can't judge it. Record the simulator during a UI test with `xcrun simctl io <udid> recordVideo --codec=h264 --force out.mp4`, stop it with SIGINT, and inspect frames with ffmpeg. Compare against a recording of the previous commit using the same test, since the simulator varies from run to run. Killing a run without stopping the recorder can leave the simulator refusing new recordings.
