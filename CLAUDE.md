# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Portfolio is a native Jellyfin client for Apple platforms, built in SwiftUI. tvOS ships first; iOS, visionOS and macOS follow and share code through `PortfolioKit`. Playback uses AetherEngine for the best video quality, including Dolby Vision Profile 7 FEL. Broad Jellyfin plugin support and ecosystem tools like Seerr are goals.

Code conventions are in @style.md.

## Commands

Everything needs Xcode 27. There's no linter. Set the destination first:

```bash
DEST='platform=tvOS Simulator,name=Apple TV 4K (4th generation)'
```

```bash
# App unit tests, as CI runs them
xcodebuild test -workspace Portfolio.xcworkspace -scheme PortfolioTV -destination "$DEST" \
  -only-testing:PortfolioTVTests -parallel-testing-enabled NO -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO

# App UI tests. These must be signed: without signing the app can't write to the Keychain,
# so the sample sign-in silently stays on onboarding and the tests fail there.
xcodebuild test -workspace Portfolio.xcworkspace -scheme PortfolioTV -destination "$DEST" \
  -only-testing:PortfolioTVUITests -parallel-testing-enabled NO -skipPackagePluginValidation

# One UI test
xcodebuild test -workspace Portfolio.xcworkspace -scheme PortfolioTV -destination "$DEST" -parallel-testing-enabled NO \
  -skipPackagePluginValidation -only-testing:PortfolioTVUITests/AppNavigationUITests/testTheSidebarOpensOnTheCurrentSection

# Package tests (run from PortfolioKit/)
xcodebuild test -scheme PortfolioKit-Package -destination "$DEST" -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO

# Playback UI tests: an Apple TV only (no video plays in the simulator), with the network
xcodebuild test -workspace Portfolio.xcworkspace -scheme PortfolioTV -destination 'platform=tvOS,name=<your Apple TV>' \
  -only-testing:PortfolioTVUITests/PlaybackUITests -skipPackagePluginValidation

# One package test (Swift Testing needs the parentheses)
xcodebuild test -scheme PortfolioKit-Package -destination "$DEST" -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO \
  '-only-testing:PortfolioSharedUITests/RootViewModelTests/showsTheRightViewForEachSessionState(_:_:)'

# Release build for a real Apple TV. Release for the simulator doesn't link (#27).
xcodebuild build -workspace Portfolio.xcworkspace -scheme PortfolioTV -configuration Release \
  -destination generic/platform=tvOS -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO

# Confirm the shared UI still builds for other platforms (run from PortfolioKit/; also visionOS)
xcodebuild build -scheme PortfolioSharedUI -destination generic/platform=iOS -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO
```

CI builds the app and runs the app unit tests and package tests on every PR. UI tests aren't in CI yet (#26), so run them locally when changing anything on screen. `-test-iterations` must be at least 2. SourceKit's "No such module" errors are noise; trust `xcodebuild`.

A simulator build with `CODE_SIGNING_ALLOWED=NO` and a signed UI test run share DerivedData, and the UI tests can end up launching the unsigned app, which the simulator refuses ("Security policy issue", or a launch `RequestDenied`). Run `xcodebuild build-for-testing` without that flag to sign it again.

Xcode and command-line builds of the workspace share one DerivedData folder, so building from the command line while the owner builds in Xcode can leave either compiling against the other's stale modules. Command-line builds alongside Xcode should pass their own `-derivedDataPath`, with `-clonedSourcePackagesDirPath` pointing at the shared folder's `SourcePackages` to reuse the packages.

Interrupting a build (killing `xcodebuild`, or a "build database is locked" failure from two builds at once) can leave later builds reporting success without relinking the app, so the simulator runs old code. Check `PortfolioTV.app/PortfolioTV.debug.dylib`'s timestamp in this project's DerivedData folder (there can be more than one), and if it's stale, delete `Build/Intermediates.noindex/PortfolioTV.build/Debug-appletvsimulator` and the built `.app` there. A clean build of everything takes about a minute, so a build running far longer is stuck rather than slow: delete that DerivedData folder's `Build` (keeping `SourcePackages`) and build again.

## Architecture

`Portfolio.xcworkspace` combines `PortfolioTV/PortfolioTV.xcodeproj` (Xcode 27's `project.xcproj` format) and the local package `PortfolioKit/`. The project uses folder references, so new files under `PortfolioTV/` join their target automatically.

**Modules**
- `PortfolioShared`: models any media server could produce, plus the saved servers, sessions and Keychain persistence. No Jellyfin types.
- `PortfolioSharedJellyfinClient`: wraps jellyfin-sdk-swift and owns everything Jellyfin-specific, such as `ServerVersion` and the SDK mapping.
- `PortfolioSharedPlaybackEngine`: the engine-neutral playback layer and `PlaybackEngine` protocol.
- `PortfolioSharedAetherPlaybackEngine`: the only module that imports AetherEngine.
- `PortfolioSharedUI`: views every platform can use, and the view models of screens each platform draws its own way (profiles and onboarding), so another platform only adds views.
- `PortfolioTV` (app target): tvOS-only views, and the composition root. `PortfolioTVApp` makes the one `JellyfinServerClient` and the `SessionManager` (Keychain storage, with the client as its authority), and passes both to the shared `RootView` along with how to make its `ProfilesView` and `MainNavigationView`, which it tells how to make a playback engine (`AetherPlaybackEngine`). `RootViewModel` hands the services to the view models it makes: a fresh `ProfilesViewModel` each time no profile is open, and a `CurrentProfileViewModel` for each fresh main UI, so every profile opens on Home.

The app target defaults to `MainActor` isolation and the package doesn't, so test suites for app code need `@MainActor`. Tests for app code go in `PortfolioTVTests`. Unit tests talk to `MockJellyfinServer`, an in-process fake built on `URLProtocol` that listens on a given scheme, host and port. It and `JellyfinServerClient.mocked`, which sends requests to it, are in `PortfolioSharedTestSupport`.

`PortfolioTV/Info.plist` sits outside the app's folder and holds only what build settings can't express: App Transport Security allows plain HTTP, because most Jellyfin servers on a home network are `http://…:8096`. Xcode merges it with the Info.plist it generates.

**Profiles and onboarding** (`PortfolioTV/Profiles/`, `PortfolioTV/Onboarding/`, view models in `PortfolioSharedUI`).
- Every launch opens on the profile picker ("Who's watching?"): everyone on every server added to this device, signed in or not, plus "Someone Else", unless Settings' Profile Picker on Launch is off: then it opens the profile opened last while it's still signed in (`SessionManager.restoreOpeningLastProfile()`, still restoring meanwhile). A fresh install opens on the welcome screen instead. No profile is open until one is picked (`SessionState.choosingProfile`). The picker starts with focus on the profile opened last (`SessionManager.lastOpenedProfile`, saved by `MediaServerStore` under its own key), without opening it.
- The open profile sits at the top of the sidebar (`CurrentProfileView`), its server's name reading "Switch Profile" while focused. Selecting it closes the profile without signing it out (`SessionManager.closeProfile()`), back to the profile picker.
- "Someone Else" on the profile picker leads to a server picker (`ServerPickerViewModel`): the servers added to this device, with their icons, where someone types their username (anyone the server lists is on the profile picker already), and "Add Server", which starts at the welcome screen.
- `SessionManager` holds the saved servers (`MediaServer`: the server, the users this device knows, and the access token of each signed-in user), stored in the Keychain by `MediaServerStore`. Opening a profile checks its token with the server first; offline still opens, and a revoked token asks for the password. Signing out keeps the profile on the picker. Settings' Remove All Servers (`SessionManager.removeAllServers()`) starts over as if freshly installed; deleting the app doesn't, because the Keychain outlives it.
- Adding a server goes welcome → address and port (without a scheme, HTTPS first, then HTTP on 8096; see `ServerAddress`) → the users the server lists (`/Users/Public`), or straight to signing in with a username when it lists nobody → their password, beside the server's branding (its icon, and its splash image and login message, if set). "Someone Else" covers users the server hides.
- `ProfilesViewModel.path` holds the pushed steps (`ProfilesViewModel.Step`) with their view models. Navigation values must be `Hashable`, so `Step` compares by view model identity: each step is equal only to itself.
- User pictures and the splash come through `JellyfinServerClient.imageURL`, as PNG at full size: those endpoints have no size or quality options, and PNG keeps the server from compressing them again. The splash fills the sign-in screen's right half without stretching (`scaledToFill`), blurred and dimmed under the server's icon and name: filling a nearly square half crops and enlarges a 16:9 image.
- The server's icon is the largest one its web client lists in `/web/manifest.json` (the file names carry a content hash in some versions, so they aren't guessed). A server without its web client gets a stand-in.
- "Use Your Phone" is a disabled stand-in for Quick Connect (#8).

**Browsing and card transitions** (`PortfolioTV/MediaBrowsing/`). The motion copies the Apple TV app and is plain SwiftUI state animation, with no UIKit or `matchedGeometryEffect`.
- `ViewState` (`.root`, `.preview`) is inherited through the environment. A browsing view at `.root` shows posters. Entering `.preview` turns the open row's cards into platters. Setting the previewed card's own `viewState` to `.root` expands it to full screen.
- A card can also go **straight from poster to full screen**, skipping the platter, with nothing else moving: its parent sets the card's own `viewState` to `.root` while it's still a poster (no change at `.root`), then enters `.preview`. Back reverses it. `MediaCardExpansionViewModel` and `MediaCardExpansionView` do this for one card, which is how the library grid opens an item. A parent view model always drives the card's states: `MediaBrowsingViewModel` for rows, `MediaCardExpansionViewModel` for a single card. The card never animates itself.
- A `RelatedMediaGroup` is drawn by `RelatedMediaGroupPosterView` at rest and by `RelatedMediaGroupCarouselView` once open. Both watch one `RelatedMediaGroupViewModel`, which holds the highlighted item, focus state, cards and where each poster is. There are two views because the open cards sit above the whole browsing view, and SwiftUI can't move a view between parents mid-animation.
- There's one `MediaCardViewModel` per item, shared by a poster and the card that grows out of it. `MediaItemLayout` is pure geometry giving each card and its artwork a frame for any point of a motion.
- `MediaBrowsingViewModel` owns the order of events. Opening places the cards exactly on their posters (which hide underneath), then enters `.preview`. Closing does the reverse.
- **Artwork:** every card draws its poster with its landscape art (the backdrop, which has no title on it, else the thumbnail) on top. The landscape art's opacity follows the card's form (`showsLandscapeArtwork(in:)`): 0 on a poster, 1 once a poster widens and on platters and full screen. That changes inside the animation that moves the card, so the picture cross-fades as the card widens, grows or shrinks. The fade has its own timing, for opacity alone: a poster filling a card that's getting wider zooms in, so the landscape art covers it quickly, early on. As a card narrows or shrinks back to a poster, it uncovers it just as quickly, early, so the poster shrinks with the card. The landscape art is only drawn while it shows, or while the card is warm (the highlighted card and `neighborsDrawn` each side), which loads it ahead of time so it's ready to fade into, and keeps only a few screen-sized images in memory.
- A card's poster always fills the card, so it grows and shrinks with it. A platter's landscape art is as big as the screen (`MediaItemLayout.artworkFrame`), and the card clips it. The open card's poster's art fills it; a neighbor's, unseen on a poster, also reaches the screen's edge on the side it moves to, since its platter's art reaches only a little past that edge while the card reaches far beyond. Cards further from the open one than `neighborsDrawn` stay posters (`waitsOffScreen`) and wait off screen, pushed as far as the furthest platter's outer edge moves, so the rest of the row slides away together, spaced as it was. Midway, the art also grows if it must to cover the part of its card on screen (`MediaItemLayout.covering`). In a row of wide cards, whose posters already show their art, opening moves the art from filling its card to where a platter's sits all the way, growing with the card; closing fits it back to its card early (by `artworkSettling`, half open) and shrinks it with the card (`MediaItemLayout.isClosing`). A neighbor's platter art is centered near the screen's middle while its card is mostly off it: closing all the way, the picture slid one way under its card while the card went the other, so the cards seemed to bounce; opening the other way, the pictures held still in their cards and then swung into place. Far cards that all waited at one spot passed over each other on the way back.
- **The carousel animates three numbers, not frames** (`RelatedMediaGroupCarouselCardsView`, an `Animatable` view): how far the row has opened (`progress`), how far the open card has expanded (`expansion`), and where the open card is while the row slides (`openPosition`). On every frame `MediaItemLayout` places every card and its artwork from that one point of the motion. Letting SwiftUI animate each card's `.position` and `.frame` and its artwork's frame on their own, on an Apple TV the open (focused) card started a few frames after its neighbors and on another curve, and the art fell out of step with its card, showing the poster around it or a second copy of the art; the simulator showed none of it. `MediaItemLayoutTests` checks that no two cards overlap and the art covers each card on screen at every step of opening, closing, expanding and sliding. The open card's artwork is centered, and each neighbor's sits `artworkParallax` toward its side, so sliding along the row moves the artwork far less than the cards. Each platter uncovers its artwork as it slides in, a parallax. Expanding uncovers the rest of the open card's artwork without moving it.
- Posters are fetched at the size they rest at and landscape art at the screen's (`MediaBrowsingView` measures the screen), so a wide poster, its platter and full screen show the very same image, which grows with the card.
- **Posters have no titles**, as in the Apple TV app. Each is drawn in its own shape (`posterAspectRatio`, from the server's `PrimaryImageAspectRatio`, so the row lays out before images load): a movie poster is 2:3, an episode's still 16:9. A wide poster shows the item's logo, small, at its bottom-leading corner, or its title if it has none, and a platter's and full screen's details show the logo in place of the title too. Logos are fetched once, at the details' size (`detailsLogoSize`).
- **Home** (`HomeViewModel`, `PortfolioTV/Home/`): a banner filling the screen that goes through the 8 newest items (`HomeBannerView`, driven by `HomeBannerViewModel`), then Continue Watching overlapping the banner's bottom, then a Latest row per library in the user's order, leaving out the libraries in their `LatestItemsExcludes` and collections, playlists and Live TV. Continue Watching is what they're partway through, then the next episode of each show they're watching that isn't already there; it's a `RelatedMediaGroup` of style `.inProgress`, whose cards are wide (480 by 270) from the start, never widen further, and show their progress, episode ("S1E5") and time left. They fetch landscape art at their own size until they're warm (`restingLandscapeArtworkSize`), so a row of them doesn't hold a screen-sized image per card.
- The banner is the browsing view's header, reaching past its safe area with negative padding (`MediaBrowsingView`'s `topPadding: 0`, and its scroll view doesn't clip). Its buttons are Play (with how far along and the time remaining, for something partly watched), Info and ›. Left and Right (and ›) move between its items; Right and › go round from the last to the first, and Left from the first brings in the sidebar. Focus stays on the button it's on through a move, and coming up from the rows lands on the button it was on last (`HomeBannerViewModel.lastButton`, Play at first). Moving on, its text and buttons fade out, then the next banner's edge sweeps in from the right (the previous one's from the left) over the one showing, uncovering its artwork in place (a mask), and the text fades back in. Its text fades out over 0.25 s and back in over 0.3 s, each logo its own view so the last one doesn't cross-fade into the next. It moves on by itself every 8 s while focus is on it (its buttons, or the catchers beside them), stopping at the last, counting again as each banner settles; with focus in the rows or the sidebar, or the player over it, it holds still on the banner showing (`HomeView.advances`); the system page indicator (`UIPageControl` with a `UIPageControlTimerProgress`, which only shows it) draws the current page as a dash filling over that time. Its details are the very block a full-screen card shows (`MediaDetailInfoView`), its buttons sitting `actionsReservedHeight` below them as a card's actions do. Info makes the banner itself the item's full-screen detail view (`HomeBannerViewModel.showsDetails`, in card motion's curve): the details move to where a full-screen card has them, and the buttons with them, since the banner's buttons are the card's actions (`MediaDetailActionsView`'s `banner`): its Play and Info are the actions' Play and Information, and its › gives way to the rest of the actions, the space between the buttons widening to the actions'. Its scrim cross-fades into a card's (`MediaCardView.detailsScrim`), and the rows fade out. Focus stays on Info, the very button that moves: as a row of its own cross-fading into the actions, Info faded out beside an Information fading in, and focus jumped to Play at the end. Back reverses it, focus staying on the action it's on, and moving to the button it was on last once it's over if that action has gone (`detailsAreMoving`, then `settled()`). Laying a full-screen card over the banner to take over instead, its actions went a frame before it did, and the buttons blinked out. While the details are away (`detailsAreAway`) the page doesn't scroll, since tvOS scrolled it to show a low button getting focus, and the edge catchers are off; only then can the actions take focus, since hidden they still drew Left and Right. The details' logo loads at `.high` priority: queued behind every poster, the banner showed none for seconds.
- An episode borrows its show's thumbnail, backdrops and logo when it lacks its own: `EpisodeInfo.seriesImages` holds the show's tags, and `MediaItem.image(_:)` gives the item's own image or else its show's, with the item it belongs to, for the resolver's URL. Jellyfin can point an episode at its season's art instead; that's left out. So its card shows the show's art and logo, and its details read "S1E5 · The Bridge · 2022 · 52m" under the show's title.
- Sections stay alive while another shows, so a section that loads from the server loads again each time it's shown (`HomeView`'s `task(id: isShowing)`), keeping its rows up until new ones arrive and leaving them untouched if nothing changed. The debug sample session's server doesn't exist, so Home says it can't reach it (which UI tests wait on to know Home is showing), it has no libraries, and UI tests use Search's sample row for posters. The library views are covered by unit tests and checked by hand against a stand-in server.
- **A load a view starts from `task` belongs to its view model, not to the task.** SwiftUI cancels and restarts Home's `task` moments after the main UI opens. A load running in that task was cancelled while a real server was still answering, and Home stayed empty. Fast mock servers answer in time, so only a slow server (a delayed stand-in will do) shows it.

Things that break easily here:
- **Card motion is a curve that stops at its end** (`layerChange`: a timing curve shaped like `.smooth(duration: 0.44)`), and **what swaps views when a motion ends waits for `.removed`**. A spring is logically complete at its nominal duration while it's still a few percent short: closing a row removed the cards there, and they jumped onto their posters, 50 points or more for a far card, worse on an Apple TV, which also stalls for a frame or two as focus moves and the carousel goes. Waiting for a spring to be removed instead left the screen still for a third of a second while it crept the last pixel. Track an edge frame by frame through a motion's last frames to see either; tiles don't show them.
- **A card shrinking back onto its poster hands it focus before its actions go** (`MediaCardExpansionViewModel.collapse`): what's behind takes focus again as the card starts shrinking (`blocksFocus`), and the poster, hidden under the card, is too faint to see rather than transparent (`hiddenPosterOpacity`). Enabled only as the actions went, tvOS picked an item page's first row for a moment; the actions taken away in the same update as focus went to the poster, or the poster transparent, put focus on the page's top, which closed it.
- **Back while a row is still opening is held until its cards have grown** (`MediaBrowsingViewModel.closesOnceGrown`), then they close straight back onto the poster, which kept focus and so is still lifted. Opening and closing move a row of wide cards' pictures along different paths, so turning round partway made them jump.
- **The carousel places its cards from the layout on every frame,** so anything the layout reads changes the motion's endpoints at once: `startsLifted` turns off only once the cards have grown, or they'd start from the smaller, resting poster.
- **Each section's page is a `compositingGroup()`** (`MainNavigationView`). A view pushed over it fades it layer by layer otherwise, and what's covered shows through: a full-screen card's poster under its backdrop, and the rows behind the card. It costs nothing at rest, only while an ancestor fades it.
- **Focus never moves while cards animate.** A tvOS focus update at the start of an animation stalls its first frames, so sequence with `withAnimation(_:completionCriteria:_:completion:)`.
- **Closing gives the poster focus just before removing the cards**, or tvOS picks a poster itself and the row's first one flashes. Focus passes through `nil` during this, and that gap mustn't count as focus leaving the row.
- `@FocusState` can only live in a view. View models take the binding as a parameter. Don't mirror focus into a view model property: the extra update breaks the close hand-off.
- **Every platter shows its actions** (Play or Resume, Information, Add to My Watchlist, Start from the Beginning) under its details, as a full-screen card does, drawn above it by `RelatedMediaGroupCarouselCardsView` since a card is a button and can't hold others. They move with the card, so growing to full screen and back fades nothing; they take focus only on the open card at full screen (`MediaDetailActionsView`'s `isActive`). Inactive, they're one hidden accessibility element, but XCUITest on tvOS still lists their buttons, so UI tests find Information inside `detail.fullScreen`.
- **Labels stay out of the motion:** the ones showing fade out as cards start moving (in their own quick animation), and the next ones fade in only once cards have stopped.
- A focused poster's card starts at the size tvOS lifts it to (`liftScale(forWidth:)`: 10.8% of its width, but no more than 40 points, which fits 4K frames of a poster, a Continue Watching card and a wide poster), so the hand-off is invisible.
- Focus staying on a poster for 5 seconds widens it in the row to at least 16:9, never narrowing one that's wider, and turns it to its landscape art; this deliberately differs from the Apple TV app, and trailers will start there. **The poster row must not be a `LazyHStack`:** it re-estimates off-screen positions from a measured wide poster and the row jumps. **A row draws only its first posters**, and always `postersDrawnAhead` (8) past the furthest focus has reached (`RelatedMediaGroupViewModel.isDrawn`), the rest being space of their own size, so it lays out exactly as it would: every poster drawn cost SwiftUI work on every frame Home scrolled (its lift effect's, among others), and on an Apple TV a Home of seven rows of 16 kept the main thread busy for about a second after each move between rows, 62 frames late over six moves, and froze 1.2 s as it first showed. Drawing half as many made it 10 late frames. A scroll view also can't scroll into width that's still animating in, so the row adds trailing room just before a poster widens. Don't keep that room permanently, or tvOS rests the last poster far from the edge.

**Settings** (`PortfolioTV/Settings/`, `SettingsViewModel` in `PortfolioSharedUI/Settings/`, preferences in `PortfolioShared/Preferences/`).
- **Laid out and moving as the Apple TV's own Settings app**, measured from recordings of it in the simulator at 60 fps: the menu's title centered at the top, its rows on the right (782 points wide, 80 from the edge, each on a white 10% capsule, in 38 points, as the system's: `headline` at medium weight, since tvOS's `title3` is 48 and a list's own text 29; text 32 points in from a row's ends, and room above and below each section's header), and on the left the menu's symbol or an image (a server's icon, someone's picture), each drawn as it is with nothing behind it, as the system draws its symbols, fitted to the same 540-point size, with the description of the row that has focus beneath it (`SettingsDescriptionView`). A row can have a tile of its own, shown while it has focus, such as a picture someone could choose. The title sits 80 points above the safe area, level with the sidebar's pill.
- **Opening a menu** is SwiftUI's own `.push(from:)` transition, in the right half: the next menu slides in from the trailing side as the one showing leaves toward the leading side, on `.smooth(duration: 0.4)`; going back runs the other way. Which way is drawn before the menu changes (`SettingsView.show(from:to:)`), since a view leaving moves as it was last drawn. Focus goes to the menu's first row, or its choice made, once it has arrived, and back to the row a menu opened from. The half clips its menus with 50 points of room past its edges, or the row with focus, which tvOS lifts, was cut off at its ends. The title and the left cross-fade only when the tile changes; otherwise they change in place. Hand-built motion (both menus' offsets and fades as state, focus kept on the leaving row) looked rough on an Apple TV. A `NavigationStack` doesn't work here: inside the sidebar's detail column it pushed each menu over the whole column, cross-fading it, and hid the title and the left, even sized to the right half. A menu with no rows that can be selected (About, Services) lets its rows take focus, or focus fell back to the sidebar and the next Menu left the app. Removing a server or signing out goes back out of its menus first, and a server is removed once its menu has gone (`SettingsViewModel.goingBack`): its menu, built again without it, had no rows, and focus was on one of them.
- `SettingsViewModel` builds each menu (`SettingsMenu`: sections of rows, each with its value, description and what selecting it does) from the preferences as they are, holds the path of menus opened, and loads what a menu lists as it opens (the server's languages and the account's language preferences, collections, playlists, server icons). A setting that's on or off changes in place; a choice goes back. Text, such as a server's address, is typed in an alert. Anything that can't be undone asks first (`SettingsConfirmation`).
- **Every preference is a flag in `UserDefaults`.** `DevicePreferences` are everyone's on this device (Profile Picker on Launch, Top Shelf, Dolby Vision FEL, upscaling, object audio and its speakers, Enhance Dialogue, Downmix to Stereo, Audio Delay, Mute Previews); `ProfilePreferences` are the open profile's, keyed by it, with how each item played last, kept for its group, an episode's show, so changing it for one episode changes it for every episode, and a movie keeps its own (so far, Style's Original; audio and subtitle tracks are the server's to remember) (Hero, streaming quality, default audio and subtitle languages, skip times, Skip Buttons, Spoiler Protection). A value saved that can't be read, such as a choice a later version took out, reads as it comes. The player reads the maximum streaming quality and the default languages (`PlaybackDefaults`); the rest are kept before what reads them is built, and the issue that builds each reads it (#37, #39 and the roadmap's chunks).
- **FEL and object audio are off unless chosen** (the owner's call). The app makes each player's engine from `DevicePreferences.playback` as it opens, so a change applies from the next play; `AetherPlaybackEngine.options(for:_:)` maps it onto AetherEngine's `LoadOptions`. Enhance Dialogue and Downmix shape decoded audio, so they decode what would pass through (Atmos, lossless) and object audio isn't rendered meanwhile.
- The default languages start out as the account's on its server (`AudioLanguagePreference`, `SubtitleLanguagePreference`), else Original and English. Hero (Home's banner) is Recently Added, a collection or a playlist, read each time Home loads. Spoiler Protection blurs unwatched episodes' artwork and hides their overviews (the `hidesSpoilers` environment value, set by `MainNavigationView`).
- Servers: each server's settings (its name, Address and Port, which must find the same server there and keep its accounts signed in, Speed Test: the quickest of three pings and a 20 MB sample from `/Playback/BitrateTest`, which needs a signed-in account), Add Server, and Remove All Servers. Accounts & Profiles: Profiles, everyone on the profile picker, and Accounts, those signed in here, signed out with a confirmation (signing out a server's last one offers to remove the server too). While signed in, someone's name and picture can be changed on their server, where every Jellyfin app shows them. Renaming sends the server the whole user, fetched first, since it saves the user's settings from the same request. tvOS has no photo picker, so the pictures are made here (`ProfilePicture`: a white symbol on one flat color, sent as a base64 PNG to `/UserImage`). Combining one person's accounts into a profile is #29. Add Server and Add Account run onboarding's steps in a full-screen cover (`ProfilesViewModel.adding(_:client:sessionManager:)`, over `.presentationBackground(.background)`: the cover's own is clear, and Settings showed through), which save the account without opening it (`SessionManager.add(_:)`), so the open profile stays open. About names the app's version and build, AetherEngine's, and each server's.
- Changing the open profile's session (a new name or picture, a server's new address) shows the main UI again, so `RootViewModel` keeps the profile's `CurrentProfileViewModel` while it stays open: a new one wouldn't share the preferences and playback progress the rest of the main UI holds.
- UI tests launch with a fresh settings suite (`PORTFOLIO_DEFAULTS_SUITE`, debug only), as with the Keychain service. A Settings row is found by its list cell's label (its title, then its value), which is what takes focus: asking for the cell around a row's button (`containing`) took minutes.

**Playback** (`PortfolioSharedPlaybackEngine`, `PortfolioSharedAetherPlaybackEngine`, `PortfolioSharedUI/Playback/`, `PortfolioTV/Playback/`).
- `PlaybackEngine` is the protocol feature code plays through: load a `PlaybackSource` (URL, HTTP headers, the version's audio and subtitle tracks and which are playing) from a position, play, pause, seek, switch audio and subtitle tracks, reduce loud sounds, stop, and observable `status`, time, duration, `surface` (the picture) and `subtitles` (drawn over it). `AetherPlaybackEngine` implements it, mirroring AetherEngine's Combine state; only its module imports AetherEngine. One engine per player.
- `JellyfinServerClient.playbackSource(for:_:session:)` asks `PlaybackInfo` for what a `PlaybackRequest` names (version, audio and subtitle tracks, a maximum bitrate or the original, where it starts; the server picks what it leaves out for the user) with a device profile claiming direct play for AetherEngine's containers and codecs at any bitrate, and HLS transcodes in fragmented MP4 (HEVC or H.264, so a remux keeps HEVC, with audio AVPlayer plays). It plays the default (first) version, or the one named: as the file it is wherever the server will (`/Videos/{id}/stream?static=true&mediaSourceId&playSessionId`), else the server's `TranscodingUrl` (else `JellyfinError.cannotPlay`), signed in by the `Authorization` header the SDK would send (`ClientIdentity.authorizationHeader`). **Direct play wins whenever the server allows it**, since any transcode loses Dolby Vision's enhancement layer and lossless audio. The server sends remuxes as transcodes too (it turns direct stream off). Tracks come from the version's streams, named by `DisplayTitle`, each `MediaTrack` saying how it arrives (`Delivery`): in the stream (subtitles in the file, `Embed`), as a file of its own (text subtitles, `External`: files beside the media, and in a transcode, those the server takes out of the file), or only in a stream the server makes (`Encode`: subtitles drawn as pictures from a file of their own, or any in a transcode, burned in; audio from a file of its own). Each answer is a new play session. `stopTranscoding` stops a stream the player has moved on from (`DELETE /Videos/ActiveEncodings`, as the web client does); the stop report stops the last. Other versions are roadmap 3.2.
- `PlayerViewModel` finds the source, loads it and plays, owning that load (not the view's task); closing stops the engine. It reports playback started to the server once it plays (`/Sessions/Playing`, with the version, play session and play method `PlaybackInfo` gave, and the audio and subtitle tracks playing, which the server remembers for next time if the user has it), where it is every 10 s and whenever it pauses or plays (`/Sessions/Playing/Progress`, as often as Jellyfin's web client), and where it stopped when it closes (`/Sessions/Playing/Stopped`: the end, if it played to the end, so the server marks it watched). Starting lists the session on the server's dashboard and stamps the item's last played date; each progress report and the stop save the position. A failed report changes nothing on screen. **Reports go one after another** (`PlayerViewModel.send`): a progress report arriving after the stop would save its position over the stop's. `CurrentProfileViewModel.makePlayer` makes one for an item from the profile's server. `MainNavigationView` presents `PlayerView` as a full-screen cover, so Play anywhere plays over everything, and Menu closes it.
- **Choosing tracks and quality** (`PlayerViewModel`): a choice the engine can make in the stream playing (audio in a file played as it is, subtitles in the stream or in a file of their own), it makes at once. Anything else (audio in a transcode, subtitles the server draws in, or taking them out again, and any quality) asks the server for another stream like it with the change, from where playback is, plays it from where playback has got to (paused if it was; the bar holds there meanwhile, and keeps the media's length, `knownDuration`, since AetherEngine says zero for both while it opens a stream. AetherEngine also opens the file again at the playhead to switch audio tracks or Reduce Loud Sounds, its clock at zero meanwhile, so `AetherPlaybackEngine` holds its time where playback was until the clock is back, `RebuildHold`: the bar went back to the start, and a progress report then would have saved zero), reports progress with it, and has the server stop the one it left. A newer choice replaces one on its way, a stream it won't play after all is stopped too, and if the server can't send one, the stream playing plays on. Qualities are Auto (the file as it is wherever the server will send it so), Original (the file as it is always, even where the server would make a stream, such as above its limit for connections from outside its network: the server sends any file as it is when asked, `static`, whatever `PlaybackInfo` decided; what only a stream could carry, such as picture subtitles in a file of their own, is left out, and it can buffer), then the bitrates Jellyfin's web client offers below the file's (`PlaybackQuality`). Original or Auto while the file plays as it is opens nothing again. Auto streams no faster than Settings' Maximum Streaming Quality, and a player starts in Settings' languages (`PlaybackDefaults`): Original is the audio track the file marks default, a language its track, and none in it keeps the server's pick; the subtitle language only swaps subtitles the server would show, never forced ones. Once the server's answer lists the tracks, they change in place in a file played as it is, else the server is asked again before anything plays, and stops the stream it made first. The source found ahead of Play asks as a player starts, so it's still used. Subtitles On shows those shown last, else the first in Settings' language, else the ones the file marks default. Style lists Original, then the system's caption styles (`CaptionStyles`, MediaAccessibility's public profiles since tvOS 26), and chooses one of those for every app, as the TV app's does. **Original** (`showsOriginalSubtitles`, off until picked, and kept as each item played last, `ProfilePreferences.showsOriginalSubtitles(for:)`: for an episode, as its show did) draws subtitles as the file has them: text in its own colors, white otherwise, with a soft shadow and no box (`CaptionStyle.original`, through `drawsOriginalSubtitles`), and pictures as the disc drew them. **Picture subtitles show only with Original**, since nothing can restyle them. Without it they can be chosen but stay off, Style as it was (`heldPictureTrack`): picked in Language, the server's pick as a player starts (forced ones too), or showing when a system style is chosen. **Original never turns subtitles on**: On then shows the pictures chosen, Off forgets them, and On shows text unless Style is Original or the file has only pictures; while one has focus, how subtitles would look with it shows near the top (`MACaptionAppearanceExecuteBlockForProfileID` reads a style without choosing it). Reduce Loud Sounds is AetherEngine's night-mode compressor (the TV app's turns on the system's Late Night Mode, which apps can't), remembered between players: it decodes audio that would pass through as it is (Atmos and lossless), each change reopens the audio for about a second, and it can't apply to a transcode, whose audio AVPlayer owns.

In a transcode, AVPlayer draws subtitle files itself and they aren't drawn twice.   - Cast & Crew: circles that grow with focus (the system's highlight drew a rounded square around them); selecting someone does nothing yet (#44).
  - Related: posters that grow straight to full screen, as a library's do, whose Information opens their page over this one.
  - About: the overview and the scores, each a tile.
  - A block of facts: Information, Languages, Accessibility, and the file (its picture, dynamic range with Dolby Vision's profile, level and enhancement layer, audio, container, size and bitrates).

  The overview tile and each column open their full text in a panel (`MediaDetailPanelView`).
- **Jellyfin lists a season with new episodes among the latest as the season itself**, which has no page here, so `recentlyAdded(for:in:limit:)` puts its show in its place, once, with `MediaItem.hasNewSeason`, asking for the shows together.
- **The page is built ahead**, once the card is full screen and settled (`MediaDetailActionsView.Metrics.pageBuildDelay`), so Information or Down only reveals it: built as it opened, it held up the scroll. Home's banner's actions are in use from the start of its move to its detail view, so it builds the page only once that has settled and focus is on them (`buildsPage`). It waits off screen, not faded out, as a view that starts out transparent never takes focus, even once it shows, and is one accessibility element without its identifier meanwhile, since XCUITest on tvOS still lists what's hidden. Back at the card, it's hidden again for the next Down; the card shrinking lets it go. Only the card's actions build and let go of pages; the page's own, at its top, did too and threw it away as it was built. An episode's page is built ahead too, once focus has rested on its text in its show's row as long (`MediaDetailPageView.Metrics.episodePageBuildDelay`), and let go once focus leaves it: built as it opened, it held up its own fade, and its details came in after. Its card is the same each time (`MediaDetailViewModel.pageCard(for:)`), so the page built is the one that opens, and one still fading out doesn't count as built. **Only the backdrop and the logo read how far it has scrolled** (`MediaDetailPageView.Scroll`): kept on the page, every frame of a scroll built the whole page again.
- **A default focus of none is still a default focus.** The actions under Home's banner, hidden and disabled, asked for focus on no action (`.defaultFocus` with nil), and kept focus from the banner's own buttons: Home opened on the first row, and Right from Play didn't reach Info. They ask only when there's an action to start on (`InitialFocus`). Their modifiers stay the same as they come into use, only what they hold changing: switching the whole row between two forms as Home's banner's details started moving rebuilt every glass button, and the move started late.
- **Focus drives the scrolling.** Moving between the card's actions and the sections scrolls between them (`ScrollViewReader`), as does focus first going into the sections as the page opens; within the sections, tvOS scrolls to what has focus. Focus coming back from a panel or a similar item's card, from nowhere on the page, stays where it is (`isEntering`): scrolled to the sections' top as well, the page jumped up and back as a panel closed. Back at the top, the page hands over to the card, which it still looks just like, on the action that has focus (`MediaDetailAction`, which each actions view tracks with its own `@FocusState`), or its first if the card hasn't that action: the page can always play, a sample row's card can't, and focus went nowhere. **The hand-over is in the same update as the page goes**: a moment later, tvOS had picked the card's Play itself, which lit up on its way to the action that had focus. tvOS still replays its focus animation on the card's button, for about 0.1 s.
- **The full-screen card shows what its page's top does:** the file's format badges after its metadata (`MediaVersion.badges`: 4K or HD, the dynamic range, Dolby Atmos, DTS:X or surround, SDH or CC) and Starring and Director at its trailing side, from the item's details (`MediaItemDetails`). They're asked as the card first expands (`prepareDetails`): a row's platter as it's highlighted, a library's poster as it starts to grow, Home's banner's item as it shows. Items like it are asked along with them, so its page opens on them, and the page's pictures load as it's built ahead. `CurrentProfileViewModel` asks each once and shares the answer; a page opens on what's known already, rather than waiting on asks that have ended.
- **The rating's panel** (`MediaDetailRatingView`) grows out of the star as the player's menus grow out of their buttons (their glass panel, row style, springs and timing), focus moving in once it has nearly grown, while the other actions are disabled. It's drawn over the actions row, placed over the star's measured frame: in the star's own overlay, the system glass button, disabled once focus was in the panel, took the presses of everything drawn in it. Across its stars lie focus stops, one for no stars and one per half star, too faint to see (`Row.stars`): Left, Right and swipes move focus along them as tvOS moves focus, and the stars show where it is. One row handling Left and Right itself missed some presses, and the Select after them. Select keeps the rating focus is on, Menu closes without changing it, and Clear Rating takes it back; closing enables the star again and moves focus to it before the panel shrinks, or focus fell to Play.
- `JellyfinServerClient.details(of:session:)` reads `/Items/{id}` (people, studios, release, countries, tagline, critics' score, and the first version's file as `MediaVersion`); `similarItems(to:session:limit:)` reads `/Items/{id}/Similar`. People's pictures come through `MediaImageResolver.url(for: Credit, pixelSize:)`. Release dates are days, which Jellyfin gives as midnight UTC, so they're formatted in UTC.

**Images** (`PortfolioSharedUI/Images/`).
- Item images come from a `MediaImageResolver`; `JellyfinImageResolver` builds Jellyfin's URLs. Each asks for a pixel size (rounded up to 100 px steps), at quality 100, naming no format, so the server sends JPEG, or PNG for transparent images such as logos. Jellyfin's image endpoints need no sign-in. User pictures, the splash and server icons have no size options and come at full size.
- `ImagePipeline.shared` downloads and decodes off the main thread, keeping decoded images in memory and data on disk (`URLCache`). It runs 8 downloads at once (`DownloadScheduler`), starting the most wanted waiting one first: a card's landscape art and the banner's backdrops are `.high`, posters `.normal`, and what's loaded ahead `.low`. Home asks for every poster of every row at once, and without priorities the art a card grows into waited behind them. Images a view shows stay in memory however full the cache gets (`ImagePipeline.lease`, held by `RemoteImageViewModel`'s layers), so a card growing out of a poster draws the poster's image from its first frame: a screen-sized backdrop is about 33 MB at 4K, a few pushed the posters out of the cache, and cards opened on blank placeholders. Like `URLSession.shared` behind `AsyncImage`, it's shared rather than passed down.
- `RemoteImageView` draws an image already in memory at once, from the first frame, and fades in one that arrives later.
- Cards wait for their artwork on `ImagePlaceholderView`: a translucent gray (the system's resting platter), with a shimmer sweeping over it while the image loads (`isLoadingImage`, set by `RemoteImageView`). The shimmer is drawn from a `TimelineView`, not animated, so it never joins a card's motion.

Things that break easily with images:
- **A cross-fade during a motion is the opacity of an image that's already there, changed inside the motion's animation.** Adding an image view, or changing the image one shows, while a card moves drew blank frames under tvOS's focus highlight, left the new image at a stale size, and blended the old image at its old size. `.animation(_:value:)` around a new image animated its size on the fade's curve, out of step with the card.
- **Anything that shows a card's landscape art changes inside the motion's animation, or after it.** Opening a row widens the poster under the open card only once the cards have grown; widening it first switched the card to landscape art at once, with no fade.
- **Handling a move command doesn't stop tvOS moving focus,** into the sidebar for one. The banner catches Left and Right with a focusable view each side of its buttons, focusable while there's a banner that way (`HomeFocus.bannerLeftEdge`, `.bannerRightEdge`). Each sits right beside the buttons, the left one in the margin left of Play (the row of buttons is pulled left by its width, so Play lines up with the text): tvOS chose the sidebar over a thin target far from the buttons.
- **Focus can't move to, or stay on, a view faded out entirely, or a clear one:** the catchers are black at 2% opacity, and the banner's buttons fade only to 2% while banners move, too faint to see, so focus stays on a button, or waits on a catcher, through the move. Faded out entirely, a button lost focus to nowhere as the banner moved on by itself. A catcher stays focusable while it holds focus even once there's nowhere left to go that way. Asked to move off a catcher after a move, focus didn't, so the catcher stops being focusable first (`releaseEdges`), then focus is set a beat later, once the buttons are back.
- **Don't keep a scroll position for the browsing view** (`scrollPosition(_:)`): it puts the scroll view back whenever the view updates, such as while a row opens or closes. Home scrolls to its top with a one-off request instead (`MediaBrowsingView`'s `scrollToTopRequests`), when focus comes up into the banner.
- Every row is a `focusSection()`, so Up and Down always reach the next row, landing on its nearest poster, even where none is directly above or below. Going back to the row focus just came from lands on the poster it left there instead (`MediaBrowsingViewModel.posterLeftBehind`, a `.defaultFocus` with `.userInitiated` priority on each row); moving on from the next row forgets it.
- **Hide rows by disabling them as well as fading them** (`MediaBrowsingView`'s `showsRows`). Faded out, Continue Watching still overlapped the banner's detail view, and its focus section, with nothing in it to focus, caught Right from Play there, so the other actions couldn't be reached.
- **A focus section only guides moves from outside its frame.** Continue Watching overlaps the banner's bottom, so a section around the whole banner wasn't "above" its cards, and Up from any card not under a button went nowhere. The section is a strip as wide as the screen around the banner's buttons, entirely above that row.
- **What's drawn inside a poster stays out of accessibility.** The poster button carries the item's name as its label. A wide poster's title appearing and fading inside it made XCUITest (and so VoiceOver) report nothing focused afterwards.
- **Cards' buttons draw their label as it is** (`MediaCardButtonStyle`), never `.borderless`: tvOS lifts each image in a `.borderless` button's label on its own, with its own corners and shadow. On an Apple TV a backdrop drew its own corners inside its moving card, and a poster's corners grew the moment focus came back to it as its card closed. Posters lift with `.hoverEffect(.highlight)` on the whole card; platters show focus by the others' darkening. Check motion on an Apple TV as well as the simulator.
- **Never fade an image out.** A view fading out keeps its last layout, so inside a moving frame it shows beside the new one. Images that go, go at once, once they're covered.

**tvOS behavior that shaped the design**
- The sidebar is a `NavigationSplitView` starting at `.detailOnly`. Search is its first section, as in the Apple TV app, but the app opens on Home. Its sections are `MainSection`s, built from the profile's libraries (`MainNavigationViewModel.mainSections` and `otherSections`), in two list sections; the second's header draws the separator. Its rows are spaced apart with `listRowSpacing`, which tvOS only has from 27. A `.sidebarAdaptable` `TabView` always opens with focus on its sidebar, and nothing moves it out (`@FocusState`, default focus, placement APIs and UIKit focus requests were all tried).
- Sidebar rows must be `NavigationLink(value:)`: `.tag`ged labels get no focus highlight, and buttons don't change the selection. These rows bring the collapsed "‹ Home" pill. It can't be hidden: removing `.sidebarToggle`, hiding the navigation bar of the sidebar or of a section, hiding the tab bar (`.toolbar(.hidden, for: .tabBar)`) on a section or the split view, and fading the sidebar's contents all left it there.
- A button as a row of its own in that sidebar doesn't take focus at all, so the open profile is a button in the section's header. Header content sits closer to the edges than rows, so `CurrentProfileView`'s insets are measured to give its focus highlight the rows' exact edges.
- Sections stay alive in a `ZStack`, so a hidden one must stay disabled or it can take focus.
- `navigationTransition(.zoom)` renders as a cross-fade on tvOS.

**Checking motion.** Tests can't judge it. On an Apple TV, Instruments' Animation Hitches template gives every frame's time and length, and what the main thread did meanwhile: `xcrun xctrace record --template 'Animation Hitches' --device <udid> --all-processes`, then `xctrace export` the `displayed-surfaces-interval`, `hitches` and `time-profile` tables. Start it 15 s before a UI test drives the screen (started as the test installs the app, it disconnects), and give the test targets the team on the command line (`DEVELOPMENT_TEAM=…`), since only the app target has it locally. Smooth in the simulator doesn't mean smooth on the TV. Record the simulator during a UI test with `xcrun simctl io <udid> recordVideo --codec=h264 --force out.mp4`, stop it with SIGINT, and inspect frames with ffmpeg. Compare against a recording of the previous commit using the same test, since the simulator varies from run to run. Killing a run without stopping the recorder can leave the simulator refusing new recordings.
